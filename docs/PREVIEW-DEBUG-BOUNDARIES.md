# 预览可视调试：边界虚线（规格待实现）

> 用户 2026-10-12 提出的调试工具。**尚未实现**，本文件是规格，实现时按此做。
> 归属：`adj905k`。

## 一、它要解决什么

本轮排查「上下拍子对不齐」时，我**连续两次判断错**：

1. 拿 `segments.perBeat`（墨迹口径）当"逐拍对齐"判据，误报 18 处；
2. 以为 `segments` 可以用来定位拍位，实际它是墨迹坐标、只有 aug 段的 `x` 是格坐标。

两次都是"**靠推断**判断边界在哪里"。项目铁律（`AGENTS.md` 六之二·3）写着
「同一个 bug 修到第三次，**换"量法"**而不是继续补分支」—— 这个开关就是那个"量法"：
**把布局内部的三套边界直接画出来，一眼就能看出谁在哪、谁和谁没对齐。**

## 二、开关的层级与生命周期（用户明确）

| 要求 | 层级 | 落法 |
|---|---|---|
| **默认关** | L0 代码默认 | store 初始值 `false` |
| **只在一个运行期里有效** | **L3 会话级**（`AGENTS.md` §七） | 内存（Zustand 非持久化 state） |
| **下次运行恢复默认关** | L3 | **不写 `localStorage`**，重开即重建 |

⚠ 按 `AGENTS.md` §七：**L3 必须每实例独立**（应用窗口 / 插件预览各自的实例互不影响）。
⇒ **不要**加到 `ijipu.*` 的持久化偏好里（那是 L1）。

## 三、开启后画什么（用户原话）

> 「在**段层、音符本体(墨迹)边界，有效(时值)边界**。每个边界处画一条**竖向的虚线**，
> **左边界只画上半部(到音符中线处)**，**右边界只画下半部**，
> **相邻音符交替不同的边界线颜色**，以方便你我来判断实际的绘制位置」

### 三类边界（每类都要能单独开关，便于对照）

| 边界 | 数据来源 | 含义 |
|---|---|---|
| **段层边界** | `PlacedToken.segment` 相关的段内容区（`xContent0` / `xContent1`）、每个段层音符的 `x` / `rightX` | `{bz}` / `{dsb}` / `{tp}` 的块与内容区 |
| **音符本体（墨迹）边界** | `note.x`（墨迹左缘）、`x + min(占宽, digitSlotW)` 或 `rightX`（墨迹右缘）—— 即 `AGENTS.md` 五·9 的墨迹口径 | 字形实际占的矩形 |
| **有效（时值）边界** | 拍位栅格：`beatToX(beat)` / 段层的 `gridX(beatAbs)`；以及 `note.width`（步进右端） | 「这一拍从哪里到哪里」 |

### 画法

- **竖虚线**（`stroke-dasharray`），贯穿该行音符的上下范围；
- **左边界**：只画**上半部**（从行顶到**音符中线** `note.y` 附近）；
- **右边界**：只画**下半部**（从**音符中线**到行底）；
  ⇒ 同一条边界的"左/右"在上下两半各显一半，**相邻边界不会糊成一片**；
- **相邻音符交替颜色**：按 `barIndex + 序号` 的奇偶取两种颜色，便于区分"这是第几个音的边界"；
- 三类边界各用一个**色系**（或划线样式），使"墨迹边界 vs 时值边界"一眼可分。

### 与既有虚线的关系

`engine/layout/guides.ts` 已是"排版虚线收敛"的纯函数层（`AGENTS.md` 五·3：预览层只消费不重算）。
⇒ 本功能应**加在 `guides.ts`**（新增一类 guide），由预览层**传入开关**决定是否消费，
**不得**在渲染端另算一套几何（五·9 + 六之二·4「数值口径必须同源」）。

## 四、验收方式（实现后的断言）

1. **默认关**：不传开关时，`guides` 输出里**没有**这类边界（负对照）；
2. **开关为 L3**：`localStorage` 里**不出现**该键；重开 store 后回到 `false`；
3. **几何同源**：断言"调试虚线画出的 x"与"布局给出的 `x` / `beatToX` / `gridX`"**逐个相等**
   （不是"接近"）；
4. **两条布局路径**（`space` / `duration`）**与三类段型**（`bz` / `dsb` / `tp`）都有覆盖
   （六之二·5）。

## 六、附：实现它之前必须知道的一个发现（adj905k 实测）

排查「段层上下没对齐」时量到，**同一个"多拍音符"在引擎里有不止一条段构造路径**，且口径不同：

```
末小节主旋律音符（`3 - - -`）: x=434.6  w=99.1  rightX=533.7  dur=4
  元素列: undefined(x=428.2) undefined(x=457.0) undefined(x=485.7) undefined(x=514.5)
          ↑ el 标记缺失、cellX 缺失 ⇒ 不是 layout/index.ts:2383 那套产生的
          ↑ 且段起点 428.2 比音符自己的 x（434.6）还靠左 ⇒ 段与音符本体用了不同锚点
```

对比：`layout/index.ts:2383` 那一套会给段打 `el`（`note`/`aug`/`dot`），而这条路径**没有**。

⇒ 后果（今天踩到的）：
- 只给一条路径补"格左缘"（`cellX`），**对不上这条路径** ⇒ 段层依旧对不齐；
- 而"照抄主旋律的列"又会把段层某些拍挤到 3.9px，撞红 `AJ1`/`AJ2`/`Y3`/`AK3`
  （那四条是"段层**内部**子拍宽按自己的时值比例"的用户口径）。

**所以这个调试开关不只是"方便"，它是解开这条线的前提** —— 必须先把
「段层边界 / 墨迹边界 / 时值边界」三套几何同时画出来，才能看清：
① 这条路径画在哪；② 它的锚点为什么比音符本体还靠左；③ 段层该对齐到哪一套。

实现时**先做时值边界**（第五节第 1 步），并**同时覆盖两条段构造路径**（六之二·5）。

**先把这个开关做出来（或先打印三套边界的实际值），看清后再动手**。
