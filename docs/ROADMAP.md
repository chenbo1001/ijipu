### 力度参与发声（强弱单 / 力度记号）

- **用户口径**：「力度作为后继强弱单控制需要用得上，先补充这块的变量，后面再来强化」。
- **现状（adj451 已完成的部分）**：
  - 音频侧：`PlayEvent.gain`（**力度倍率**，缺省 1）——`schedulePlay` 按 `0.5 × gain` 给后端；adj427 已用于「重叠伴奏/第二声部 = 0.75」。
  - 色块轨道侧：`PlayheadSeg.gain`（与应用 `playheadTrack` 条目、插件 `PlayheadSeg` **同源透传**）——力度变量已贯通「事件 → 拍段 → 轨道」，后续算出的逐音力度会**同时**作用于音频与色块，无需再改数据结构。
  - 记号侧：渐强/渐弱（`<` `>` `!`）目前**只参与排版**（`layout/hairpins.ts`，含行尾未闭合处理），**尚未参与发声**；`&mp` 等力度文本同样只显示。
- **后续强化要做的事**：把 `hairpins.ts` 解出的 hairpin 区间与起止力度映射成**逐音 `gain`**（渐强 0→1、渐弱 1→0，可配基准力度），写进 `buildPlaySequence` 的事件 `gain`；MIDI 导出（`eventsToMidi`）同步把 `gain` 写进 note-on velocity（目前固定 90）。

### 色块视觉完善（应用 + Obsidian 插件）

- **现状（adj452 已完成的部分）**：两端的色块规则已统一——按 **(页, 曲行, 声部, 音色, 声部角色)** 逐块绘制，高度优先用引擎的 `yTopMin`/`yBottomMax`（多声部按声部中线分块、临时段按上下层分块），缺省回退 `[y − 1.6×字号, y + 0.6×字号]`；配色 = `playVoice` 固定色（bz 上层蓝 / dsb 下层绿 / dsb 上层红）→ 音色调色板 → 声部号。插件侧规则抽在 `obsidian-ijipu/src/playhead.ts`（纯函数、有断言）。
- **可继续完善的方向**（用户：「后面再考虑怎么完善」）：

## 实施顺序建议

```
M1 ✅ → M2 → M3 → M4 → M5 → M6 → M7 → M8 → M9 → T1（桌面）→ B1-B3（云端）
```

- **M 系列**：本地核心功能，按 M2（体验）→ M3（联动）→ M4（试听）→ M5 → M6 → M7 推进；M8/M9 可穿插。
- **T1 桌面打包**：M 系列完成后实施（本地优先原则）；Rust 工具链安装与沙箱实测为其第一步。
- **B1-B3 云端**：最后实施（用户明确：先实现本地化功能，再考虑上网服务）。
- 每期结束：`npm run build` + `npm run lint` + `npm run smoke` 全绿，git 里程碑提交。
- **每次出错**：30 分钟内记录到 docs/ERRORS-LOG.md（现象/根因/解决/预防），并复核其预防清单。
