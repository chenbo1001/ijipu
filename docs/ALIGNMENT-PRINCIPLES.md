# 上下对齐原则（用户口径，作为冒烟判定的依据）

> 用户在 2026-10-12「段层上下对不齐」这条线上逐条给出的口径。**这是判定的依据**：
> 写断言、改布局、判断"修好没有"都以本文件为准。
> 由 `ijipu/AGENTS.md` §五 引用（自动加载），避免只躺在文档里失效。

## 一、三层对齐原则（用户原话，有先后次序）

> 「多声部、临时多声部、临时伴奏的对齐其实也是这个原则，**首先要保证拍子起点和宽度对齐**，
> 再保存**同时值起点的左边界对齐**，后保存**同时值长度的右边界对齐**，这是上下对齐的主要原则」

| 层 | 内容 | 说明 |
|---|---|---|
| **① 基础** | **拍子起点 + 宽度对齐** | 每拍的**位置**与**宽**在上下两层一致。这一层不成立，后面两层无从谈起 |
| **②** | **同时值起点的左边界对齐** | **时值相同**的音，左边界必须落在同一列 |
| **③** | **同时值长度的右边界对齐** | **时值长度相同**的音，右边界必须落在同一列 |

⚠ 三层是**递进**的：① 做不到时，②③ 只能"事后兜底"，兜不出来就是 ① 的账
（本轮实测：段层每拍步进 `25.7` vs 主旋律时值格 `28.8` ⇒ ① 不成立）。

## 二、时值格与墨迹的关系（左缘定位点）

> 「拍子墨迹应该是要在**时值格**里的，所以墨迹左缘一定是在时值格内的，也就是左缘右侧，
> **时值格左缘 x ≤ 墨迹左缘 x**，同理 **时值格右缘 x ≥ 墨迹右缘 x**。
> 这个时值左缘可能是**拍子的左缘**，也可能是**音符块的左缘**，看它定的是谁的时值，
> **这也是色块的左缘定位点**。」

- **时值格**是权威几何；**墨迹必须落在格内**（不是"大约"）；
- **格左缘**按"它定的是谁的时值"取：可能是**拍子的左缘**，也可能是**音符块的左缘**；
- **色块左缘 = 时值格左缘**（同一个点，不许各算一套）。

## 三、时值格右边界的取法

> 「时值格的右边界按上面说的原则，如：**下一个时值格的左缘**，**避开无时值元素**等」

```
时值格右缘 = min( 下一个时值格的左缘 , 小节线左界 , 无时值元素（&zkh/&ykh/&hx 等括号/修饰符）左缘 )
```

另有两条补充（用户早前口径，已落地在 `adj374`/`adj905c`）：

- **末音**（没有"下一个时值"）取自己的**末格右缘**，含增时线/附点（`adj374` 要求色块盖住末格增时线）；
- 「**播放层不变，只是色块显示层有变化**」—— `playheadSegs` 是**色块专用**数据，
  调它的水平几何**只影响显示**，播放数据（`atMs`/`durationMs`/`pitch`/`instrument`）与布局层都不动。

## 四、间隙（`NOTE_GAP`）的归属与作用

> 「插间隙的**只针对多声部/伴奏**的情况，**单声部不在内**，因为多声部/伴奏本就考虑到
> 以**最小本体占宽**来计算可用留空（即间隙）了，这个间隙就是为了填充在音符块之间以
> **保证同时值点的音符块左边界对齐**，只是这一块内容之间没做到/做好」

- 间隙的**目的**：填在音符块之间，使**同时值点的块左边界对齐**（服务于 ① 与 ②）；
- **范围**：多声部 / 临时多声部 / 临时伴奏（段层）。**单声部不在内** —— 不要为此改单声部的 `n.width`；
- 常量一次定义：`layout/index.ts:213` 的 `NOTE_GAP = 4`，模型是「n 拍有 (n−1) 个间隙」（`:616`）。

## 五、段层末小节的对齐

> 「**段层末小节无小节线的末尾与主旋律的小节一对齐**，主旋律一定是要有的」

段层（`{bz}`/`{dsb}`/`{tp}`）末尾可能没有收尾小节线，但它的**内容右端必须与主旋律那一小节的
右端（小节线 / `rightX`）对齐** —— 主旋律那一侧一定有小节线可作锚点。

实测（首页「铃儿响叮当」末小节）：段层末音右缘 `533.7` == 主旋律 `rightX` `533.7` ✅ **已满足**。

## 五之二、【基准占宽怎么定】不是"谁优先"，而是"最大本体宽度"（用户 2026-10 澄清）

> 「不是谁优化的问题，而是**计算这拍里的最大本体宽度**，作为**基准占宽**。
>  增时线只有一条横线，因此通常怎么计算都是**段层更宽**，那当然**以段层为基准**了。
>  更直白点好：**与增时线对齐的，以"非增时线的段层"为基准**；
>  如果**有多个声部，还是以最大本体宽度为基准**。」

**规则（判定与实现都以它为准）**：

1. **一拍内先算"最大本体宽度"** —— 该拍上各层元素里，**本体（墨迹/字形）最宽的那个**；
2. 以它为**该拍的基准占宽**；
3. **增时线（`-`）本体只是一条横线**（极窄）⇒ 它的"本体宽度"最小，
   所以**通常段层比它宽** ⇒ **与增时线对齐时，以段层（非增时线的那个）为基准**；
4. **多声部**时同理：**仍取最大本体宽度**为基准（不是取某一个声部特权）。

⚠ 这条**替代**了此前我在对话里提的"拍位对齐优先 / 内部比例优先 二选一"——
那个提法本身是错的：**不存在"谁优先"，而是基准由"最大本体宽度"算出来**。

⚠ 与之配套的既有约束：**层落位**（段层音符的 `x`）必须与主旋律**音符位**逐个相等
（`adj435` / `AL1` / `O4` 三条守着的"11.2px 跳变"就是破坏它的后果，实测已复现过一次）；
**色块左缘**才用"时值格左缘"。两者**不能混用**。

## 五之三、【实施草图】按"最大本体宽度为基准"改段层拍位（下一步，`adj905t`）

用户口径见 §五之二。当前实测差距（首页「铃儿响叮当」末小节）：

```
主旋律 `3 - - -` : 每拍 24.8（`-` 本体只有一条横线 ⇒ 本体窄）
段层   `1, 3, 5, 3,`: 每拍 28.8（真实数字 ⇒ 本体宽）
⇒ 按原则基准应取 28.8（段层）⇒ 主旋律增时线所在的拍要按段层加宽
```

**为什么不能是"改一个数"**：主旋律**先排**、段层是**叠加后处理**，所以要让主旋律的增时线格去听段层的本体宽，
需要三件事一起做：

1. **新增一趟"每拍基准占宽"扫描**：先把各层在同一拍上的**本体宽度**收集起来，取 `max`；
   （本体宽度按 `AGENTS.md` 五·9 的墨迹口径取，**增时线只算一条横线**）
2. **主旋律排版消费该基准**去排增时线/附点的格；
3. **重算行内适配** —— 主旋律小节总宽会变大 ⇒ 牵动 `segScale`、`xContent1`、行宽守恒。

⚠ 第 3 步碰到的是**行宽/段宽/压缩**这条最敏感的链
（`adj433/437/441/444/629/674/705/710` 十余次修补都在那里），
**必须先用调试线（`docs/PREVIEW-DEBUG-BOUNDARIES.md`）看清改前改后各条线的位置**再动。

**验收方式（现在就能用）**：打开「预览可视调试」，
**绿线（`segment` 段层）与红线（`beat` 拍子）应当逐拍重合**；青线（`aug` 增时线）落在对应拍内。

**已被证伪的替代做法（别再试）**：

| 试法 | 结果 |
|---|---|
| 把 `beatToX` 统一到"格列"（含音符起点） | **精确复现 `adj435` 警告的 11.2px 跳变**，撞红 `O4`/`AL1`/`AJ1..4`/`Z18`/`Y3`/`U5` 共 10+ 条 |
| 只在音符内部按格列（保留起点走 `n.x`） | 末小节段层落到真格列 ✅，但撞红 `AK3[时值优先]` + 我的过时断言 `adj905i` |

⇒ 关键约束：**层落位（音符 `x`）与色块左缘是两套口径，不许混用**（见 §六 前的说明）。

## 五之四、【用户裁定 ①】逐拍对齐主旋律的格 + 拍宽按最大本体宽度为基准（`adj905v`）

> 用户 2026-10 裁定（原话）：「**① 逐拍对齐主旋律的格，拍宽按最大本体宽度为基准**」

### 公式（已验证思路，下次直接实现）

```
beatToX(拍) = 主旋律该拍的格 segments[k].x
              + 数字在格内的偏移 off = n.x − segments[0].x      （实测 6.4px，两条段构造路径一致）
```

**为什么这个写法能同时满足两类不变量**：

- 第 0 拍 ⇒ `segments[0].x + off = n.x` ⇒ **等于"数字位"**，
  `adj435`/`AL1`/`O4` 守的"上下层数字逐个相等、不许 11px 跳变"**自动满足**；
- 其余各拍 ⇒ **步进自动等于主旋律的格** ⇒ 逐拍重合。

**实测效果（`adj905t` 探针，改前/改后）**：

```
                   主旋律拍列            段层拍列                  步进
改前（现状）    56, 85, 113.9, 142.9   62.5, 87.5, 112.4, 137.4   29 vs 25 ❌
改后            56, 85, 113.9, 142.9   62.5, 91.5, 120.4, 149.4   29 vs 29 ✅
```

### 随之**必须改写**的 5 条断言（口径变更，不是放宽）

用户裁定 ① 之后，下列断言编码的是**旧口径**（"段层内部按自己的时值比例"），
与"逐拍对齐主旋律的格"在**时值不同**时**数学上不能同时成立** ⇒ 按 ① 重写：

| 断言 | 旧口径 | 新口径（用户裁定 ①） |
|---|---|---|
| `AJ1`（空间/时值优先） | 段层同拍 3 个子拍宽 ≥ 数字净宽 | 仍须"不重叠"，但**宽度由主旋律该拍的格决定** |
| `AJ2` | 段层子拍宽比 ≈ **2:1:1** | **比照主旋律同拍的格宽比**（不再强制 2:1:1） |
| `AJ3` | 段层子拍宽之和 = 主旋律同拍字距跨度 | 同左，但"字距跨度"改按**格列**算 |
| `AK3` | 段层每拍宽均匀（`8 : 2'/ : 3'/` = 2:1:1） | **比照主旋律该三拍的格宽** |
| `Y3` | 段层占宽 ≈ 包络跨度 | 段层占宽 = **各拍格宽之和**（对齐后自然与主旋律一致） |

### 落地结果（`adj905v`，2026-10-12 已完成并冒烟守住）

实现落在 `packages/ijipu-engine/src/engine/layout/index.ts` 的 `beatToX`（段层叠加层的拍位映射）：

```
拍位 b 落在主旋律音 m 的第 j 格
  ⇒ x = 格 j 左缘 + t × (格 j 右缘 − 格 j 左缘) + off
    off       = m.x − m.segments[0].x          （"数字在格内的偏移"）
    格 j 右缘 = 格 j+1 的左缘（§三）；**末格**取本音符自己的收尾 `zoneEnd`
    t         = (b − 该格起拍) ÷ 该格拍数
```

`segments` 缺失时（理论上不应发生）回落旧写法（`[n.x, zoneEnd]` 内按本音时值线性插值）。

**实测（`docs/ALIGNMENT-DEBUG-SAMPLES.md` 例 1，时值优先路径）**：

| | 主旋律拍列 | 段层拍列 | 步进 |
|---|---|---|---|
| 改前 | 56, 85, 113.9, 142.9 | 62.5, 87.5, 112.4, 137.4 | 29 / **25** ❌（25 = 本音块宽 99.8 ÷ 4，**不含** `NOTE_GAP`） |
| 改后 | 56, 85, 113.9, 142.9 | 62.5, 91.5, 120.4, 149.4 | 29 / **29** ✅ |

⚠ **两条布局路径上"重合"的含义不同（实测）**：

| 路径 | `off` | 绿线（段层）与红线（拍子）的关系 |
|---|---|---|
| **时值优先**（`DUR_CFG`） | ≈ `6.4`（数字在**拍槽内居中**） | 段层 = 格 + **常量 off** ⇒ **恒差一个 off**（步进相同、不再逐拍累积） |
| **空间优先**（应用默认） | `0`（该路径 `segments[0].x` 就是**数字位**） | 段层 = 格 ⇒ **逐拍重合** ✅ |

⇒ 上面"绿线与红线逐拍重合"是**空间优先**路径的准确描述；时值优先路径按 `adj435` 的要求
（第 0 拍必须 = **数字位**）保留常量 `off` —— 两者**不可兼得**："数字在格内居中"本身就是那 `6.4px`。

### 连带修掉的三处（都是这条口径逼出来的）

1. **末格的右缘取"本音收尾"**（不是"格宽 × 拍数"）：否则段层末音会伸进拍间隙，
   且 `Y3`（段层占宽 = **各拍格宽之和**）会被切短；
2. **撤销 `adj705` 的"末音相位夹紧"**：它按"线性相位 × 包络跨度"重算末音右缘，与**格**不同源 ——
   实测把 `3'/`（0.5 拍）从格右缘 `304.3` 切到 `294.5` ⇒ 段层占宽少 `9.8px`。
   它当年要的"段内增时线与主旋律对齐"已由格列映射**自动达成**（`adj905j` 的 `gridX` 同源）；
3. **【真缺陷】`fillWholeBarLongNotes`（`adj673`）前移到段层落位之前**：它声称"不动 x"，但会
   **重写 `n.segments`（格列）**，排在段层之后 ⇒ 段层对齐到的是**旧格**。实测首页「铃儿响叮当」
   末小节（`3 - - -` 独占一小节，空间优先）：段层 `439.7 / 467.9 / 496.1`
   vs 最终格列 `451.0 / 480.6 / 510.1` ⇒ 末拍差 **`14px`**（见 `E-2026-407`）。

## 六、明确**不采用**的方案（用户否掉）
> 「**不推荐 B**（按页面有效宽度定义每个时值的宽度），这就是**等时值**的布局方式，
> 这会导致**短时值音符之间很窄，而长时值音符之间又很松**」

⇒ **禁止**把"整小节均分成 N 格、每格等宽"当作通用布局口径。
