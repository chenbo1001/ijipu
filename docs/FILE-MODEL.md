# 文件模型与「能力降级」口径（adj966）

> **一句话**：打开/保存的对象**统一是"一个系统文件"**；各端按**自身能力**决定"能不能无手势读写、能不能监视外部改动、
> 能不能跨会话保留这份绑定"，能力不足就**降级**（退草稿 / 要一次手势 / 手动打开），
> 但**任何端都不许静默覆盖别人的修改**。

## 0. 为什么要有这份口径（用户实报）

一份 `.jps` 在同步端（另一台机器 / Obsidian / 网盘同步）被改过之后，本端因为**编辑内容缓存**（草稿）并不知道，
于是"基于旧内容的保存"把**最新修改覆盖**掉。插件端已经解决了这件事（宿主 `modify` 事件 + 基准比对）；
PC 端与 Web/PWA 端要按**同一套口径**补上，而不是各写一套。

## 1. 三条不变量（所有端共同，判据落在 `src/store/externalChange.ts`）

1. **打开/读入时**记**基准** = 内容指纹（归一化）+ 当时的 mtime（`setBaseline`）。
2. **写盘前**与基准比对（`probeExternalChange`）：不一致 ⇒ **不静默写**，弹三选
   （保留本地 / 载入外部 / **查看差异**，复用既有 `FileDiffDialog`）。
3. **写盘成功后**立刻刷基准（`setBaseline`）、并登记"在途写"（`markWriteInFlight`）⇒ **自己写的回环**永远落在
   "指纹一致"那一支（`adj927`/`adj943` 已解决"自己写盘反而提示外部变更"）。

## 2. 能力接口（判据**只**在 `src/store/fileHost.ts` 一处定义）

| 能力 | 含义 | 桌面壳（Tauri） | 插件嵌入版 | Web（Chromium） | PWA（安装版） | 其它浏览器 / 手机 |
|---|---|---|---|---|---|---|
| `open` | 打开方式 | 原生对话框 / 原生路径 | 文库文件（宿主桥） | 文件选择器（FSA） | 同 Web | `<input type=file>`（只读一次） |
| `readWithoutGesture` | 无手势读当前内容 | ✓ | ✓ | ✓（句柄在手即可 `getFile()`） | ✓ | ✗ |
| `writeWithoutGesture` | 无手势写回 | ✓（原生） | ✓（宿主桥） | **看权限**（§3） | 同 Web | ✗ |
| `watch` | 外部改动检测 | `poll`／将来 `event` | `event`（宿主 `modify`） | `poll` + 聚焦/可见时检查 | 同 Web | `none` |
| `hasMtime` | 有 mtime 可快筛 | ✓ | ✗（宿主只推 `path`，见 `externalChange.ts` 头注释） | ✓（`File.lastModified`） | ✓ | ✗ |
| `persistBinding` | 绑定跨会话 | 草稿里的原生路径 | 宿主记录（文库路径） | IndexedDB 句柄 | IndexedDB | ✗ |
| `needsGestureForWrite` | 写回是否要手势 | ✗ | ✗ | **未持久授权时要** | 同 Web | ✓ |

> 这张表就是"**按能力降级**"的全部依据：**同一套交互**（打开 → 编辑 → 自动/手动保存 → 冲突三选），
> 差别只在"哪一格是 ✗ 时退到什么"。**缺能力不是缺功能，是缺到某一档为止。**

## 3. Web/PWA 的权限分档（决定"能否取消草稿"）

- Chrome **122** 起，文件选择提示是三选一：「仅此次」/「**每次访问都允许**」/「不允许」；
  选「每次访问都允许」⇒ 该 origin 对该文件**无需手势、跨会话**可读写（站点设置里的「文件编辑」可撤销）。
- 默认（仅此次）：权限**只活到该 origin 最后一个标签页关闭**为止 ⇒ 重开后 `createWritable()` 抛
  `NotAllowedError`（项目实测记在 `store/saveSupport.ts` 头注释，`adj363`）。
- `FileSystemObserver`（真正的**事件**监视）目前是 Chrome **源试用** ⇒ **只当加速项**，不能当依赖；
  保底 = **轮询 + 页面重新可见/获得焦点时检查**。
- **Firefox / Safari（含 iOS 上的一切浏览器与 PWA）没有 FSA** ⇒ 只能"打开=上传、保存=下载"：
  **这一支必须保留草稿**（否则一刷新内容就没了）。
- 手机端既有口径（`adj405`）：已安装的 PWA 里 `showOpenFilePicker` 不可靠 ⇒ 一律走 `<input type=file>`。

## 4. 分端步骤（逐步逐端退出"工作区"操作方式）

> **§4 之零：分层口径（用户 2026-10-17 拍板，`adj966g` —— 谁走工作区、谁走系统文件）**
>
> 用户原话：「**需要权限确认的（可能就手机端 Web 这种模式）还继续使用工作区底栏**；
> 其它可以直接使用文件系统的 **PC 端的各模式，还是继续使用系统文件操作**（这样可能更习惯）；
> **插件还继续使用 OB 端的文件管理方式**」。
>
> | 档 | 文件入口 | 底栏默认页 | 「打开…」 |
> |---|---|---|---|
> | 桌面壳（Tauri） | **系统文件**（原生对话框 / 双击关联） | 收起（问题） | 原生选择器 |
> | 桌面浏览器（有 FSA） | **系统文件**（FSA 句柄，写回同一文件） | 收起（问题） | 系统文件选择器 |
> | 手机 / PAD 的 Web 与 PWA（要权限、拿不到可写句柄） | **工作区底栏**（选文件夹当工作区） | **展开在「工作区」** | 工作区面板 |
> | 桌面版 Firefox / Safari（无 FSA 且**选不了文件夹**） | 打开=上传、保存=下载（**留草稿**） | 收起（问题） | `<input type=file>` |
> | 插件嵌入版 | **OB 文库**（`vault`，宿主自己管文件） | 收起（问题） | 工作区面板（文库即工作区） |
>
> 两条机器判据（都在 `store/fileHost.ts`，纯函数、有闸门）：
>  · `shouldOpenWorkspaceDock(profile, canPickDir)` = `profile.id === 'limited' && canPickDir`
>    ⇒ 底栏一开始是否展开在「工作区」（`uiStore.initialDock` 接线）；
>  · 「打开…」分流（`TopBar.runOpenSmart`）：**手机/平板且能选文件夹** ⇒ 工作区面板；
>    其余**一律**系统文件选择器 / input 降级 —— **PC 上不再有"设过工作区就去开面板"那一支**。
>
> 注意：**工作区没有删**（也不打算删）。PC 上仍可从菜单「工作区」或底栏显式打开一个目录当工作区，
> 只是"点打开就操作系统文件"更符合 PC 习惯。

**A. PC（Tauri）——先做，先把默认换过来**
1. **默认以系统文件为操作对象**：打开走原生对话框/原生路径；保存写回**同一个文件**（不再要求先建工作区）。
2. **外部变更检测**：原生侧加"读 + stat（mtime）"与**轮询**（有 `notify` 事件源时升级为 `event`），
   触发既有 `probeExternalChange`；不一致 ⇒ 既有三选弹条 + 差异框。
3. **工作区降级**：从"主入口"变成"可选的组织方式"（后续版本再谈移除），**打开/保存绝不依赖工作区**。
4. 草稿保留为**崩溃兜底**，但**不再承担"最新内容"的职责**（写盘后刷基准，写前必比基准）。

**B. Web / PWA**
1. 打开/保存走 FSA 句柄（已有）；**首次授权时引导用户选「每次访问都允许」**（文案里说清"这样下次打开才能直接写"）。
2. 得到持久授权 ⇒ 与 PC 同档（无手势读写 + 轮询 + 冲突三选）；
   未得到（选"仅此次"、权限被撤销、非 Chromium、手机）⇒ **降级为草稿 + 手动保存**，
   但**保存前仍必比基准**（这一步不需要任何新权限，就能消灭"静默覆盖"）。
3. 句柄失效（`gone`）/权限丢失（`permission`）复用既有 `classifySaveError` 提示，不静默。

**C. 插件（已完成，保持）**
插件端"**无工作区**"已经落地（默认以 OB 文库为主工作区，`vault` 后端）；本轮只需**统一提示与差异口径**
（沿用同一份 `externalChangeCopy` / 差异框行为），不重复造一套。

**D. 统一交互（三端同一套）**
打开 / 保存 / 另存为 / 冲突三选 / 差异查看 / 「已保存 · 耗时明细」的**文案与顺序一致**；
菜单项只按能力显隐（例如没有 FSA 的浏览器不显示"直接写回"）。文案集中在 `brand/copy.ts`。

## 5. 判据（要进 `npm run smoke`）

- `fileHost.ts` 的**能力表与降级决策**是纯函数 ⇒ 逐端逐档断言（含负对照：把某一格改成相反值，决策必须随之改变）；
- 「写盘前必比基准」：伪造"外部已改" ⇒ 决策必须是"提示"而**不是**直接写（负对照：基准一致 ⇒ 允许直接写）；
- 「自己写的回环不提示」：`markWriteInFlight` + 刷基准后 ⇒ 判 `unchanged`（既有 `adj927`/`adj943` 断言保留）；
- 三端文案同源：`externalChangeCopy` 只在一处定义（既有）。

## 6. 本文档的边界

- 它定的是**口径与分档**，不是实现细节；实现落在 `src/store/fileHost.ts`（能力与决策）、
  `src/store/externalChange.ts`（比对判据）、各端的 `readText`/`mtimeOf`/`watch` 适配器。
- Web/PWA 的"源试用 API"（`FileSystemObserver`）**不得**写成依赖；一旦转正，只换适配器实现，不改判据。

## 8. 发布前的真机确认清单（adj966）

> 发布（打 tag / 打包 / 出 Release）前，请按下面三节各跑一遍。**两处失败都不算"功能坏了"**：
> ① 轮询是"尽力而为"的检测（隐藏标签页不查），没提示 ≠ 检测失效；② 受限档（Firefox / Safari / 手机）
> **本来就不该**直接操作文件 —— 那时应看到降级行为（草稿 + 手动保存），而不是报错。

### A. Windows 桌面端（本轮改动最集中的一端）

1. **打开一个系统文件**：菜单「打开」选一个 `.jps`（或双击关联文件）⇒ 编辑区出现内容，状态栏显示文件名。
2. **保存写回同一个文件**：改几个字 → `Ctrl+S` ⇒ 提示"已保存"，且**用别的编辑器打开该文件**能看到刚才的改动。
3. **上次的工作区不再自动接管**：若你以前建过工作区，启动时应看到一条提示
   「PC 版已改为直接操作系统文件：上次的工作区不会自动打开…」⇒ 底部「工作区」面板里**显式**打开照样可用。
4. **外部改动能被发现**（关键）：保持应用打开并停在这个文件上 → 用记事本/别的编辑器把该 `.jps` 改几个字保存
   → 4 秒内应弹出「保留本地 / 载入外部 / 查看差异」；
   - 点「查看差异」应看到两栏差异（左=本地、右=外部）；
   - 点「保留本地」后再保存 ⇒ **会用本地覆盖外部**（提示里已写明这是用户选择）；
   - 自己刚保存完**不该**弹这条（那是回环，判据里专门挡住了）。
5. **系统时间/权限异常时**：把文件设为只读或删掉 ⇒ 保存应**如实报错**（不许显示"已保存"）。

### B. 浏览器 / PWA（Chrome 或 Edge）

1. 打开网站版 ⇒ 「打开」一个 `.jps`：浏览器会问权限；**选「每次访问都允许」** ⇒ 应弹出一次
   「想以后免手点保存…请在权限气泡里选『每次访问都允许』…」（只提示一次，L1 标记 `ijipu.permGuideShown`）。
2. `Ctrl+S` 能直接写回该文件（无第二次授权弹窗）；**关掉标签页再打开、再打开同一文件** ⇒ 仍应能直接保存。
3. 外部改动同样应在 4 秒内被提示（与桌面端同一条链）。
4. 若在权限气泡里选「仅此次」：`Ctrl+S` 可能要求重新授权 —— 这是**预期降级**，不是缺陷。

### C. Obsidian 插件（保持"无工作区"）

1. 库里打开一份 `.jps`（嵌入版/文件视图）⇒ 编辑后**随输随存**（400ms 合并窗口），状态栏无异常。
2. **在库外用别的程序改同一个文件**（或让 Sync 拉一份新版本）⇒ 嵌入版应弹「保留本地 / 载入外部 / 查看差异」。
3. 插件侧**不需要**任何新设置项（本轮未改插件源码；只有嵌入版跟随应用版本更新）。

### E. 两边都改了怎么办（adj966f 已实现，发布前也请跑一遍）

> 桌面端与浏览器端都能跑；**插件端也可以**（它的差异框就是应用这一份，见 §4C）。

1. 打开一个系统文件 → **本地改一处**（比如第 2 小节）→ 用别的编辑器把**另一处**（比如第 5 小节）改掉保存
   ⇒ 4 秒内弹出确认条，文案应是「两边都改了，但改动**互不重叠**（N 块）——已经自动合好…点「应用」即写回文件」；
   点「应用」⇒ 提示"已保存"，**用别的编辑器打开该文件应能看到：你改的那处 + 外部改的那处都在**。
2. 再用同样的办法造一次**真冲突**：本地改某一小节，外部改**同一个小节**（内容不同）保存
   ⇒ 确认条这次应说"要你决定"（**不**说"已自动合好"、也**不**给「应用」快捷按钮）；
   点「查看差异」⇒ 差异框里那一块标着「冲突：两边都改了同一块」、块上有「用左 / 用右」；
   选「用右」→ 点「应用（并保存）」⇒ 文件里应是**外部那一版**、本地那一版被换掉（反向选「用左」则相反）；
   应用后确认条与差异框都应关掉，且**不再反复提示**（基准已刷新）。
3. 顺手验一下护栏：应用前把本地/外部各存了一份（`ijipu.mergeBackupLocal` / `ijipu.mergeBackupExternal`），
   应用是**一步历史**（`Ctrl+Z` 应能一次撤销回合并前的本地内容），合并后若有语法问题会进问题面板。

## 9. 冲突处理：两边都改了怎么办（adj966e 定口径 / **adj966f 已实现**）

> 场景：一份 `.jps` 在同步端被改（外部），本机编辑器里也有未保存改动（本地）⇒ **两边都变了**。
> 本节的四条口径由用户 2026-10-16 拍板、**锁死不改**；实现落点见本节末尾的"落点一览"。

**用户已拍板的四条**（2026-10-16）：

| # | 决策 |
|---|---|
| 1 | **先做 P1（块级采纳），紧接着做 P2（自动三路合并）** |
| 2 | 差异框里的按钮文案：**「用左 / 用右」**（栏目标题已写明本地/外部） |
| 3 | 合并**以本地为底**（本地改动留在编辑器里、历史连续；外部改动以块为单位供采纳） |
| 4 | 采纳后**立即保存**（一步到位写回文件、刷新基准） |

**P1 块级采纳**（**已实现**，`adj966f`）：
- 差异框每个改动块给「用左 / 用右」，顶部「全用左 / 全用右」，底部「应用（并保存）」（以本地为底，逐块替换）⇒
  **应用后立即保存**；
- 合并函数做成**纯函数**（`diff/merge.ts` 的 `planMerge(base, local, external)` / `applyMerge(base, local, external, choices)`），
  逐例断言 + 负对照；
- 复用差异框**已经算好的改动块**（不另写一套 diff ✗）：行级对齐一律走 `diff/textDiff.ts` 的 `diffTexts`。

**P2 自动三路合并**（**已实现**，`adj966f`）：
- 前提：`FileBaseline` 从"只存指纹"改为**同时保留原文**（`FileBaseline.text`，内存代价 = 一份谱面文本，可忽略）
  ⇒ 有了**共同祖先**（`externalChange.getBaselineText(key)`，键对不上就是 `null` ⇒ 自动退化为 P1 逐块采纳）；
- 行级三路合并：`base / local / external` 各自 diff ⇒ **只有两边改了同一块**才算冲突（要问），其余自动合干净；
- 对 `.jps` 尤其合适：一行 = 一条语句/小节 ⇒ 同步冲突大多落在**不同小节**，多数情况**不必打扰用户**；
  无冲突块时确认条直接说"已自动合好（N 块互不重叠）"并给一个「应用」按钮（`ask.extra`）；
- **块粒度**（要说清，否则"自动合"的边界说不明白）：一个块 = **某一侧的一段连续改动行**
  （与 `git`/`diff3` 的 change-hunk 同口径）；相邻两行都改 ⇒ 一个块，中间隔一行 ⇒ 两个块。
  ⇒ "互不重叠 ⇒ 自动合"的准确含义是**两侧的改动段互不重叠**；相邻改动被并进同一块时，
  那一块会连本地没碰过的那一行**一起**交给用户选（不丢东西，只多问一句）；
- **P3 不做**：行内字符级自动合并（同一行两边都改只做"标出来让人选"，不做自动字符合并）。

**护栏（与 P1/P2 同批做，均已落地）**：
1. **两侧都不丢**：应用合并前，把「本地那份」与「外部那份」各存一份（L1 键 `ijipu.mergeBackupLocal` /
   `ijipu.mergeBackupExternal` + `ijipu.mergeBackupAt`），随时能回看；
2. **可撤销**：应用合并 = **一步**历史（先把 `lastEditAt` 清零，避免与刚敲的字并成一步）；
3. **立刻体检**：应用走 `setCode` ⇒ 解析器重算，有问题进问题面板（不静默给一份坏谱）；
4. **状态收口**：应用后**立刻写回文件**（`saveFile`）⇒ 写前登记在途写、写后刷基准，
   状态从"两边都改过"回到"已保存"（`fileHost.docStateOf`）；
5. 新增第六态 `bound-conflict`（"两边都改过" = 外部改了 **且** 本地有未保存改动），与既有五态同一张表
   （见 §7 台账与 `fileHost.docStateOf`）。
