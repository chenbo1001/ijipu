# 音色库与乐器指定语法规格（adj33x / adj344）

> 本文档定义「音色库 + 乐器」的指定语法与语义。属于 `.jps` 语法规范的一部分，
> 改动解析器后需同步 `docs/SYNTAX.md`（《脚本语法说明》）并在 `scripts/smoke.mts` 补断言。
>
> **adj344（试听简化）**：试听**固定 SpessaSynth 高保真**音源——不再提供「合成（快速）/
> midi-js 采样（高质量）」切换；「音色库」下拉移除（固定默认内置库）；导出音频同样改为
> SpessaSynth 高保真离线渲染。合成/midi-js 后端在 engine 中保留为兼容代码（标注废弃），
> 但不再作为试听用途。

## 1. 乐器引用（`@` 包裹，格式化安全）
为防自动格式化破坏乐器名（如 `@电吉他(清音)` 被拆成 `@电吉他 (清音)`），乐器指定改为 **`@` 包裹**：
- `@库id:乐器名["显示名"]@`
- 无库 id：`@乐器名["显示名"]@`
- 无显示名：`@库id:乐器名@` / `@乐器名@`

**规则**：`@...@` 之间的内容**不做自动化格式化**（原样保留，可含 `()`、`.`, 空格等），确保乐器引用安全。
- `@@`（空包裹）＝ 切回默认乐器（沿用）。
- 示例：`@电吉他(清音)@`、`@generaluser_gs:小提琴"领奏"@`、`@小提琴@`。

**兼容**：单 `@乐器名`（无尾 `@`）的旧写法**继续能解析**（按 `@` 到空白/`@` 结束），但会对**旧写法产生告警**，提示改用新语法 `@乐器名@`（含特殊字符的乐器名必须用 `@...@` 才能安全）——告警在 parser 错误/警告列表与编辑器浮层中展示。

## 2. 乐器显示名（可选）
在引用后可用引号携带显示名：
- `@乐器名"显示名"`、`@音色库id:乐器名"显示名"`。
- `"显示名"` **非必需**。
- **显示规则**（描述头标题下）：
  1. 有显示名 → 显示 `显示名`；
  2. 无显示名 → 显示**纯净的「乐器名」**（去掉 `@` 与音色库前缀，仅乐器名本身）。

## 3. Y 行（默认乐器）
`Y: <乐器引用>["显示名"]` —— 描述头默认乐器。示例：
- `Y: @小提琴"领奏"`（省略库 id + 显示名）
- `Y: @generaluser_gs:小提琴`（指定库，无显示名 → 显示“小提琴”）

## 4. 重名与省略规则
- 省略音色库（`@乐器名`）时，按 **可用乐器列表** 查找该乐器。
- **同名多库**：取可用列表中的**第一个**同名乐器，保证可正常播放。
- 需要精确指定某一库时用 `@音色库id:乐器名`。
- 「重名」的判断基准 = 所有**已可用乐器**列表（含收藏的高保真 GM 音色与 midi 库乐器）中的同名字段。

## 5. 可用乐器列表（adj344：试听固定 SpessaSynth 高保真）
运行时按用户配置动态汇聚——**试听固定高保真**，可用乐器即高保真 GM 库中用户**收藏**的音色：
- 高保真 GM 库：用户**收藏**的音色（`playbackHqEnabled`），库 id = 该音源库 id，乐器名 = GM 音色名。
- 合成 6 种 / midi 标准库不再作为**试听**可选项（engine 语法兼容保留，但试听后端固定高保真）。
列表顺序即「取第一个同类名」的先后依据。

## 6. 补全
- 取消编辑区 `@` 与 `Y:` 行乐器自动补全（列表过长不便选择）。
- 乐器插入改由**输入工具条**一步完成（携带引用 + 可选显示名）。

## 7. 播放路由（adj344：固定 SpessaSynth 高保真）
- 试听后端固定 SpessaSynth（高保真 GM）：按解析出的 `{库id, 乐器名}` 经 `engine.instrumentToProgram`
  选 GM program（`@库id:乐器名` 库前缀解析仍兼容）。
- 合成 / midi-js 采样后端不再作为试听用途（engine 兼容代码保留，仅标注废弃）。

## 8. 编辑器行号诊断（@乐器名告警在行号栏）
- 解析对旧写法 `@乐器名` 生成 `warning` 诊断（含行+列）；语法错误为 `error`。
- **行号栏渲染**：有告警/错误的行号显示对应背景色（warning=黄，error=红）。
- **优先级**：**告警/错误背景 > 当前行高亮**——同行的行号若含告警/错误，显示告警/错误色；无告警才显示当前行高亮。当前行高亮不得覆盖告警/错误色。
- **点击跳转**：点击告警/错误行号 → 光标跳到该行**问题所在列**。

## 10. 音源文件的来源与分发（adj346 / adj416）

> 这一节讲"音源本体从哪来"，与上面的语法无关；改打包方式或音源来源时同步本节与 `scripts/check-installer.mjs`。
>
> ⚠ **adj1009 起要改成"多音色库"**（库列表 / 可添加 / 可切换）：方案与现状诊断见
> **`docs/SOUNDBANK-LIBRARY-PLAN.md`**；页面与"扫描本机目录/推荐下载"见 **`docs/SOUNDBANK-PAGE-PLAN.md`**。
> 本节现有的"只有一个默认库"口径在该方案落地后作废，
> 届时按那份文档的 §五、§六 重写本节。

**来源优先级（`src/playback/spessaCache.ts` 的 `resolveHqBank`，试听/导出共用）**：
1. **IndexedDB 缓存**（`ijipu-soundfonts-hq`，键 = 库 id）——用户导入的音色文件、或 Web 端已下载的音源；
2. **桌面内置音源**——**安装目录**下的 `generaluser_gs.sf2`（见下）；
3. **远端下载**——`HQ_LIBRARIES[].source`（GitHub raw），失败再试 `fallbackSource`；**只有这一条的结果会写回缓存**。

**桌面（Tauri）内置音源**：
- 发布程序把 `resources/soundfonts/generaluser_gs.sf2` **随安装包**装到**安装目录根**：`<安装目录>\generaluser_gs.sf2`
  （`src-tauri/tauri.conf.json` 的 `bundle.resources` 映射 `../resources/soundfonts/generaluser_gs.sf2 → generaluser_gs.sf2`）。
- Rust 侧查找顺序（`builtin_soundfont_candidates`）：**安装目录根 `<库id>.sf2` 优先**，其次 `soundfonts/<库id>.sf2`（兼容旧便携版布局）。
- 前端**先用 `sf_soundfont_builtin_path` 探测存在性**（不读 30MB）：
  - 命中 → 试听/音色库面板显示「✓ 使用随应用内置音源…无需下载」并**跳过下载提示**，播放时再 `sf_soundfont_resource_read` 读字节（raw body → ArrayBuffer）；
  - 未命中（如 Web、或用户把文件删了）→ 显示原有的「正在后台下载音色库」提示并联网。
- 便携/调试目录不含随包资源，由 `scripts/prepare-tauri-soundfont.mjs` 把音源放到 exe 旁（`target/release`、`target/debug`），布局与安装目录一致。
- 校验：`npm run check:installer`（安装清单必须含 `generaluser_gs.sf2`）+ smoke `[101]`（映射/源文件为真 SF2/查找顺序/raw body）。

**Web（PWA）**：音源不打包进 Web 产物（规避单文件体积上限），一律远端下载一次后缓存到 IndexedDB，之后直接用（离线可用）。
