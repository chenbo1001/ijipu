## 1. 项目概述

### 1.1 产品定位 ✅

**JianpuScript（码上简谱）** —— 下一代代码式简谱制谱引擎。用编程语言的严谨逻辑编排中国传统简谱：音乐人像写代码一样编排音符，程序员像调参一样调整音高。**敲码即谱，所见即所得。**

### 1.2 品牌身份 ✅

| 要素 | 内容 |
|---|---|
| 英文名 | JianpuScript |
| 中文名 | 码上简谱 |
| 中文简称 | 码谱（Mǎ Pǔ） |
| 文件后缀 | `.jps`（Jianpu Pro Script） |
| 命令行概念 | `jps run` / `jps compile` |
| 用户身份 | 谱师（Score Smith） |
| 品牌色 | 深空蓝 `#1E2A5E` + 霓虹青 `#00F0FF` |
| 大标题 Slogan | 敲码即谱，所见即所得 |
| 底部情怀 Slogan | 用代码的严谨，谱写指尖的浪漫 |

### 1.3 项目背景 ✅

复刻「番茄简谱」在线编辑器（zhipu.lezhi99.com）的核心能力，采用现代技术栈重写、现代设计语言重设计。原站已确认的技术特征：`.jps` 脚本语言（服务端渲染 SVG）、Web Audio 试听、云端账号谱库、PDF/JPG/SVG 导出。

### 1.4 产品愿景 ✅

- **第一版**：纯前端单页应用，核心制谱能力完整可用，本地运行、预留公网部署能力。
- **中期（本地优先）**：Tauri v2 Windows 桌面打包（本地文件读写、离线可用）；CLI 工具（jps run/compile）可并行规划。
- **后期（云端）**：Python FastAPI 后端（账号 / 云谱库 / 服务端 PDF）。
- **远期**：成为社区化的简谱脚本平台，培养「谱师」文化。

> 决策记录（2026-08-16）：**先实现本地化功能，再考虑上网服务** —— 桌面打包（T1）优先级提到 Python 后端（B1-B3）之前。

## 4. 功能需求（FR）

### FR-1 脚本编辑器

- **描述**：编辑 .jps 文本，覆盖编辑器底座能力。
- **功能点**：
  - 语法高亮：行头命令（Q/C/B/Z/D/P/J）、音符数字、小节线、歌词、注释、`[fenye]`、`&` 装饰编码（配色见设计规范）
  - 自动格式化：Q 行空格规范（数字/小节线前补空格），防抖执行并尽量保持光标位置
  - 行首命令快捷键：Q/C/B/Z/D/P/J 在行首直接插入命令头
  - 快捷键体系：Ctrl+N/O/S/Q、Tab 切换预览、Ctrl+~ 符号速查
- **验收要点**：输入 `1 1 5 5` 立即正确着色；勾选自动格式化后输入 `Q:1 2|` 自动变为 `Q: 1 2 |`。

### FR-2 实时渲染预览

- **描述**：.jps → 解析 → 排版 → SVG 乐谱，随输入实时刷新。
- **功能点**：
  - 三视图：编码 / 拆分（上预览下代码）/ 预览
  - 乐谱按 A4/A5 纸张渲染，支持多页（`[fenye]` 手动分页）
  - 谱面元素：标题/副标题居中、作者居右、调号/拍号/节拍、音符（3 套字形）、小节线、反复记号、跳房子、连音线、歌词逐字对齐
- **验收要点**：小星星示例渲染结果与简谱规范一致；每行自动换行不超过页面宽度。

### FR-3 光标双向联动

- **描述**：编辑器光标 ↔ 乐谱音符位置互跳。
- **功能点**：
  - 编辑器光标移动 → 乐谱对应音符出现红色光标块并自动滚动
  - 点击乐谱音符 → 编辑器光标跳到对应位置
- **验收要点**：任意位置光标移动，预览区音符一一对应。

### FR-4 页面设置

- **描述**：纸张（A4/A5/横版）、四边距、标题/副标题/歌词字体字号、音符字形样式（a/b/c）、行间距（曲上/曲下/词下，可按页覆盖）、连音线样式（自动/圆弧/平顶）。
- **验收要点**：修改后预览即时重排；设置随谱子持久化。

### FR-5 导出

| 格式 | 方案（第一版纯前端） |
|---|---|
| SVG | 直接下载每页 SVG |
| PNG / JPG | SVG → canvas（可含背景）→ 下载 |
| PDF | 浏览器打印（每页 A4 SVG）或 jsPDF 合成 |

- **验收要点**：多页谱导出为对应格式，内容与预览一致。

### FR-6 试听播放

- **描述**：按音符序列 + 反复记号逻辑播放。
- **功能点**：
  - 速度 30~200 拍/分钟（从 J 描述头推断默认值）
  - 自动滚屏、播放中音符高亮、点击音符跳转播放
  - 反复记号：`|:` `:|` 反复、跳房子 `[]`（第一遍/第二遍）
  - 音色：Web Audio 合成（默认）+ 钢琴采样（可切换，采样按需加载）
- **验收要点**：两只老虎示例按反复记号正确播放。

### FR-7 内置示例谱

- 排排坐（极简，冒烟用）/ 小星星（歌词对齐）/ 两只老虎（反复记号）
- ⚠️ 待补充：是否内置原站示例（时间都去哪了等，涉及版权，需需求方确认授权来源）。

### FR-8 本地存储

- 自动草稿（localStorage，每次输入保存）
- 保存/打开为 .jps 文件（下载/上传）
- ⚠️ 待补充：是否需要「本地谱库」（IndexedDB 管理多份谱子 + 文件夹分类），还是仅单文档草稿。

## 6. 技术方案

### 6.1 技术栈 ✅

| 层 | 选型 |
|---|---|
| 前端框架 | React 19 + TypeScript（strict）+ Vite 8 |
| 状态管理 | Zustand |
| 引擎 | 纯 TS：`source → parse → layout → render / playback` |
| 音频 | Web Audio API（合成音色自研；采样音源可选加载） |
| 存储 | localStorage（草稿）/ IndexedDB（谱库，待定） |
| 后端（后续阶段） | Python FastAPI（账号 / 云谱库 / 服务端 PDF） |

### 6.2 架构与数据流 ✅

```
.jps 源码 ──parse──▶ ParseResult（AST）
     ──layout──▶ ScoreLayout（多页坐标模型）
          ├──render──▶ SVG（预览 / 导出）
          └──playback──▶ 播放序列（合成/采样）
```

### 6.3 开发环境适配（DSH 沙箱）✅

- npm 命令统一加 `--cache "D:/Coding/JPCoder/.npm-cache"`
- `scripts/patch-vite.js` 适配 Vite 的 `net use` 探测 spawn 限制
- 冒烟测试通过 vite 打包 CJS 后 node 运行（`npm run smoke`）
