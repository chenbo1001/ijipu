# 全局「音色库」页面优化方案（发现 → 推荐 → 管理 → 选音色 → 使用）

> 状态：**方案待拍板**（2026-10-21 起草）。落地编号从 `adj1013` 起（当前最新 `adj1012`）。
> 定位：`SOUNDBANK-LIBRARY-PLAN.md`（多库架构：解析 / 注册表 / 接线 / 列表）的**页面与发现层续篇**。
> 那份解决"库能不能被区分、被切换"；这份解决"**库里有什么、从哪来、用户怎么一步步用上**"。

---

## 一、先说结论：四层，每层只回答一个问题

| 层 | 回答的问题 | 不是什么 |
|---|---|---|
| ① 音色库列表 + 推荐 + 下载 | 「我**有哪些**库？想再要一个去哪拿？」 | 不是音色列表 |
| ② 音色库管理 + 导入/导出 | 「这个库的**文件**在哪、多大、要不要换/删/导出？」 | 不是选音色 |
| ③ 音色选择管理 | 「这个库里**哪些音色**我要用？」 | 不是试听 |
| ④ 音色的使用 | 「选中的音色**在哪里生效**？」 | **不是页面里的一组按钮** —— 它是下游（试听下拉 / 导出音频 / `Y:` 语义 / 色块配色） |

一句话口径：**先发现本机有什么，再谈推荐下载；先有库，才谈选音色；选完音色才谈"用在哪"。**
页面按这四层从上到下排，顺序就是用户的操作顺序。

## 二、现状与差距（现在为什么"放进目录也看不见"）

| 现状 | 缺什么 | 用户会看到什么 |
|---|---|---|
| 库列表 = 引擎里的**已知清单**（2 条）+ `libs` 表里**已登记**的记录 | 没有"扫描目录"这一步 | 把 `xxx.sf2` 拷进 `soundfonts/`，应用里**没有它** |
| 桌面只按**已知 id** 探测 `<id>.sf2`（`sf_soundfont_builtin_path(lib_id)`） | 只能"查指定名字在不在"，不能"列出目录里都有什么" | 改个文件名就认不出 |
| 插件只按**已知 id** 拼 URL（`bankUrls()` 遍历 `HQ_LIBRARIES`） | 同上，插件目录里的其它 sf2 它不看 | 插件目录放 3 个库，只认 1 个 |
| Web 只能列出 IndexedDB 的键（`listBankKeys`） | 键没登记就没有库名/音色数 | 缓存里有字节，界面显示"未加载" |
| 推荐 = 引擎里两条元数据（名称/体积/许可/下载页） | 没有"为什么推荐它"、没有空状态引导 | 第一次用的人不知道该下哪个 |
| 下载/导入的落点：桌面写 **IndexedDB**、插件写插件目录 | 桌面没有"写进文件目录"的路 | "下载了，但文件去哪了？" |

## 三、发现：三端各自"去哪找、能不能写"

| 端 | 扫描哪里 | 读 | 写 | 权限现实 |
|---|---|---|---|---|
| **桌面（Tauri）** | ① 安装目录根 + `安装目录\soundfonts\`（随包/用户手动放的） ② `%APPDATA%\<app>\soundfonts\`（**下载与导入落这里**） | 都能读 | **只有 ② 能写** | 安装目录通常在 `Program Files`，普通用户**没有写权限** ⇒ 「下载自动存到 soundfont 目录」只能落到 ② |
| **插件（Obsidian）** | `<配置目录>/plugins/<插件 id>/soundfonts/` | `vault.adapter.readBinary` | ✅ 能写（随文库同步） | 已经在用，扩成"列目录"即可 |
| **网页 / PWA** | IndexedDB：`ijipu-soundfonts-hq` 的 `banks` + `libs` | ✅ | ✅ | 没有"目录"这个概念，缓存就是它的目录 |

> ✅ **已拍板（2026-10-21）**：桌面端**不能**把下载写进安装目录（权限），所以——
> 安装目录只放**随包内置**那份（只读），用户下载/导入一律进 `%APPDATA%\<app>\soundfonts\`；
> 扫描时**两处都扫**，列表里标清楚「随包」还是「本机」。
> 顺带的好处（用户口径）：**卸载不会删掉用户自己攒的音源**。
>
> 随包那份**不自动**复制到 APPDATA（不白占 32 MB）；真要复制，是一个显式动作（见 §十二）。

## 四、扫描怎么做（成本、限制、为什么不能"一次读全量"）

### 4.1 扫描只读"头"，不读采样

一次扫描要回答的是「**有哪些文件**、**各是什么库**、**多大**」，不是「每个库有哪些音色」：

| 步骤 | 读多少 | 得到什么 |
|---|---|---|
| 列目录 + `stat` | 0 字节 | 文件名、字节数、修改时间 |
| 读文件头 256 KB | 每文件 256 KB | `INAM`（库名）、`IENG`、`ifil`；足以判断"是不是 SF2、叫什么" |
| 文件名兜底 | — | 读不到 INAM 时用文件名（`FluidR3_GM.sf2` → `FluidR3_GM`） |

### 4.2 音色表为什么"首次选中再读"

SF2 的结构是 `RIFF → LIST INFO → LIST sdta（采样）→ LIST pdta（预设表）`——
**`pdta/phdr` 在文件尾部**。也就是说"读出音色列表"这件事**天然要读到接近文件末尾**：

- GeneralUser 32 MB、FluidR3 141.5 MB；
- 扫描目录时对每个文件都读全量 ⇒ 打开设置页要几秒到十几秒，不可接受；
- 所以：**扫描只登记"轻量元数据"**（库名/体积/路径/是否在），
  **音色表在该库第一次被选中（或第一次展开）时读一次全量、解析后存进 `libs.presets`**，
  之后永远读缓存（Phase 2 已经是这个设计，只是当时只有"导入"一条路能有元数据）。

界面上如实写：`287 音色`（已解析）/ `音色数未知（选中后读取）`（未解析）——**不猜**。

### 4.3 扫描结果分三类（都要显示，不能静默）

| 类别 | 判据 | 界面 |
|---|---|---|
| 已登记·文件在 | `libs` 有条目 + 扫描到同指纹文件 | 正常行，标 `随包/本机/已导入` |
| 已登记·文件不在 | `libs` 有条目，扫描不到 | 灰行 + 「文件不在了（重新下载/重新导入）」，**不自动删条目**（用户可能只是拔了盘/换了机器） |
| 发现·未登记 | 扫描到文件，`libs` 没有 | 自动登记（`origin` 按位置），标「已发现」，音色数待解析 |

### 4.4 去重与优先级

同一份内容（大小 + 头尾指纹相同）出现在两个目录时，**只算一个库**，优先级：
`随包（安装目录）> 本机（APPDATA）> 插件目录 > 缓存`。
理由：随包那份是"一定存在"的基线；用户自己下载的版本可能半截/被改过。

## 五、推荐列表（空状态用它，平时也能看）

### 5.1 三种做法，选哪一种（2026-10-21 用户要求"分析一下哪种好"）

| 做法 | 好处 | 坏处 | 结论 |
|---|---|---|---|
| **A 全都做"应用内一键下载"** | 用户点一下就好 | ① 多数免费库没有 CORS 友好的直链（FluidR3 实测只有 HTML 页、无 `Access-Control-Allow-Origin`）；② 141 MB 下载失败率高，还要做进度/重试；③ 每条都要我们承担"下到的是不是音源"的责任 | ❌ 不做 |
| **B 只做"推荐 + 理由 + 打开下载页"，用户自己下、自己导入** | 零带宽、零 CORS、许可责任清楚；**任何库都能进来**（不限于清单） | 用户要跳两次：下载页 → 回来「添加音色库…」 | ✅ **主口径** |
| **C 混合**：能直下的给一键，不能的给页面 | 兼顾体验 | 需要逐条核实"能不能直下"，清单一变就得改代码 | ✅ **只留窄口** |

**最终：B 为主 + C 的窄口。** 具体三条：

1. 应用**只保证"基础库"开箱可用**：桌面随包 GeneralUser；网页/插件首次使用走官方直链，失败就引导手动导入。
2. 推荐清单**只给信息**（库名 / 体积 / 许可 / 音色数 / 推荐理由 / 下载页），**不承诺一键下载**；
   用户自己决定下不下、下哪个，下完用「添加音色库…」导进来。
3. 只有"**直链稳定 + CORS 允许 + 体积可接受**"三条同时满足，才额外给 `[下载并导入]`。
   当前只有 GeneralUser 满足（FluidR3 不满足，见 `SOUNDBANK-LIBRARY-PLAN.md` §5.4 实测）。

> "国内下载方不方便"怎么写：只写**可核实的事实**与**该走哪条路**，例如 FluidR3 那条写
> 「发布页在 SourceForge，请用「下载页」自己下；应用内无法代下（源站返回 HTML 且无 CORS）」。
> 不写"很快/很稳"这种没有依据的话。

## 七、数据模型（在 Phase 2 的 `BankRecord` 上扩，不重做）

```ts
// 扫描结果：**瞬时**的，不写入 libs
export interface DiscoveredBank {
  location: 'install' | 'appdata' | 'plugin' | 'cache'
  fileName: string
  /** 桌面/插件用路径或 URL；缓存用库 id */
  ref: string
  sizeBytes: number
  mtimeMs?: number
  /** 只读头得到的（可能没有） */
  infoName?: string
  fingerprint?: string
  /** 认领到的库 id（内容指纹 + INAM） */
  libId?: string
}

// 库记录（libs 表）：在现有字段上加四个
export interface BankRecord {
  // …现有：id / name / fileName / sizeBytes / format / origin / addedAt / presets
  /** 文件现在在哪（解析顺序：随包 → 本机 → 插件） */
  location?: 'install' | 'appdata' | 'plugin' | 'cache'
  /** 本次扫描是否还找得到（false ⇒ 界面标"文件不在了"，但不删记录） */
  present?: boolean
  /** 预设表是否已解析（false ⇒ 界面写"音色数未知（选中后读取）"） */
  presetsKnown?: boolean
  /** 文件修改时间（用于"文件换了要重新解析"的判断） */
  mtimeMs?: number
}
```

**"发现"与"登记"分开**是这份方案的关键结构：扫描只产出 `DiscoveredBank[]`，
登记（写 `libs`）是下一步；这样扫描可以随时重跑、不污染库表，也便于"扫到什么算什么"。

## 八、扫描流程（三端共用一套编排，IO 各端注入）

```
scanLibraries(io):
  files = io.scan()                      // 三端各自实现
  out: DiscoveredBank[] = []
  for f in files:
      head = io.readHead(f, 256KB)        // 桌面/插件读文件；缓存直接读 ArrayBuffer 头
      if !isSf2(head) → 跳过（并记一条"坏文件"给界面的诊断区）
      info = readSf2Info(head)            // 引擎纯函数（截断安全）
      fingerprint = fingerprintOf(head + size)   // 轻量指纹：不读全量
      out.push({ ...f, infoName: info?.name, fingerprint, libId: bankIdOf(info, fingerprint) })
  # 去重：按 libId，按 location 优先级保一个
  # 登记：对"未登记"的写 libs（presets: [], presetsKnown: false）
  # 标记：对"已登记但这次没扫到"的 present=false
  return out
```

> 指纹用"头 64 KB + 尾 64 KB + 长度"（引擎 `fingerprintOf` 已有）；扫描阶段连尾都不用读，
> 用"头 + 长度"也够区分——**同一长度的两个不同 sf2** 极少见，真撞了由 INAM 兜住。

**P5 / P6 已落地的东西（2026-10-21）**：

- Rust 四条命令：`sf_soundfont_scan` / `sf_soundfont_peek`（头尾各 64 KB）/ `sf_soundfont_store`（`fs::copy`）/
  `sf_soundfont_delete`；`builtin_soundfont_candidates` 也认 `<app_data>/soundfonts`。
- `bankDiscovery.ts`：`discoverBanks(io, now)` 是纯编排（smoke 用假 IO 真跑），
  `createAppDiscoveryIo()` 负责桌面（Tauri）与网页（只有缓存）的差异。
- **指纹同口径**是这一步的隐藏难点：扫描只读头尾、导入读全量，两边都走
  `fingerprintOfParts` / `fingerprintOf`（同一算法），否则同一文件会出现两行。
- 界面还没接上（P8）：现在 `discoverBanks` 只有 smoke 在用。
- 扫描**不读缓存字节**：缓存里"有哪些库"只看键，记录里已有名字/体积/预设表 ⇒
  141 MB 的库不会每开一次设置页就从 IndexedDB 读一遍；只有"没有记录的老缓存"才真读一次。

**P7 / P8 已落地（2026-10-21，adj1016）**：

- 引擎 `HqSampleLibrary` 加 `reason`；`RECOMMENDED_BANKS = HQ_LIBRARIES.filter(有理由)`。
  两条推荐的理由都只写**可核实的事实**（体积/音色数/首次加载快慢/许可），不写"音质最好"。
- `SoundBankPanel` 按四层重排，**并把发现接进来**：
  - 打开面板 → `scanAndRegister()`（扫三处 + 登记）→ 再准备当前库（探测内置/预取/补预设表）；
  - 顶部一条「当前使用」摘要；扫描状态行写清"三个位置各扫到几个"；
  - 空状态：三条出路（下载推荐 / 导入本地文件 / 重新扫描）+ 三个位置的探测结果；
  - 推荐区：一个库都没有时**自动展开**；
  - 行上标 `随包 / 本机 / 缓存 / 文件不在了`，文件不在了**不让删记录**、只提示放回去再扫；
  - 坏文件进诊断区（"跳过 N 个文件 / 看原因"），不静默吞掉；
  - 第 4 层「使用」**只有说明**（试听/导出/`Y:` 是它的下游）。
- `presetCountOf` 修了口径：`presetsKnown === false` 时**不拿空数组当 0 个音色**，
  而是回落到已知库的实测值（还没有就显示"音色数未知（选中后读取）"）。

  音色库页的"点了要动"目前只能手测，或者以后单独加一段 CDP 用例（用 `DOM.setFileInputFiles` 选文件 +
  读 `localStorage` 验证切库）。

**环境备注（2026-10-21 实测）**：本机 `cargo test --lib` 在**加载期**就崩
（`0xc0000139 STATUS_ENTRYPOINT_NOT_FOUND`，即 DLL 入口点问题），把 `src-tauri/src/lib.rs` 退回
改动前的版本**同样崩** ⇒ 与本轮代码无关，是环境问题（AGENTS 已记过"沙箱隔离了 WebView2 初始化"）。
所以 Rust 单测**写了但没跑**，如实记在这里；换一台机器或修好环境后 `npm run test:rust` 应能直接跑。

**手测（负向优先）**：
1. 把 `FluidR3_GM.sf2` 拷进 `%APPDATA%\...\soundfonts\` → 打开页面**不用点任何按钮**就能看到它（名字来自 INAM，不是文件名）。
2. 把文件改名成 `abc.sf2` → 仍然认成 Fluid R3（按内容，不按名字）。
3. 把文件删掉 → 行变灰写「文件不在了」，**不自动删库、不切走当前库**。
4. 放一个 `.txt` 改名成 `.sf2` → 诊断区写"跳过 1 个坏文件"，不崩。
5. 两个目录放同一份文件 → 只出现一行，标"随包"优先。
6. 扫到未知库 → 点「使用」→ 音色数从"未知"变成真实数字（首次解析），刷新页面后仍是数字（已缓存）。
7. 网页版无缓存 → 空状态三出路都在；点「下载推荐」能下完并自动出现在列表。

## 十一、风险与边界

| 风险 | 处理 |
|---|---|
| 安装目录不可写 | 下载/导入只写 APPDATA；页面明确标"随包（只读）" |
| 扫描慢 | 只 `stat` + 读头 256 KB；不解析音色表、不读采样 |
| 用户以为"音色数未知"是 bug | 文案写「选中后读取」，选中后立刻变成真实数字 |
| 扫描到 50 个文件把列表撑爆 | 按库名分组 + "已登记/已发现/文件不在"三段；超过 N 条折叠 |
| 隐私 | 只扫自己的两个目录，**不外传**任何文件名；页面里写一句 |
| 坏文件/半截下载 | 记入"诊断"区（跳过 N 个），不阻断其它库 |
| 与 Phase 2 迁移冲突 | 扫描只登记"未登记"的 id；迁移仍按 `ijipu.soundbankLibsV2` 跑一次 |
